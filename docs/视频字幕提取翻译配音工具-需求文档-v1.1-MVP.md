## 3. 自建需求

### FR-1 探测与内封字幕直出

**输入**：视频文件绝对路径
**行为**：

1. `ffprobe` 探测：视频流、音轨（数量/语言/编码）、字幕流（数量/语言/编码）。
2. 字幕流分类：
   - **文本型**（`subrip`/`ass`/`ssa`/`mov_text`/`webvtt`）→ 走 A 路线
   - **图形型**（`hdmv_pgs_subtitle`/`dvd_subtitle`）→ 判为不支持，给出明确提示并终止（不静默降级）
3. A 路线：`ffmpeg -map 0:s:N` 抽出并转 SRT。
4. 多轨选择优先级：`语言标签匹配源语言` > `未标记的第一条文本轨`；**`forced` 轨一律跳过并告警**。
5. 无文本字幕流 → 输出"需 ASR"的路由结论，交由底座 `/recogn`。
6. 产出 `manifest.json`：探测结果、路由决策、决策理由、警告列表。

**实现补充（M2 已定）**：

- **路由优先级链**：非 forced 文本轨 → 语言标签匹配源语言 > 未标记语言的第一条 > 第一条（退化为第一条时必告警）。语言标签做别名归一（`zh`/`zho`/`chi`/`cmn`/`zh-CN`/`chi-Hans` 都算中文；`und`/`mul`/空 算未标记）。
- **文本轨与图形轨并存**：抽文本轨并告警跳过图形轨，不整体失败。
- **未知字幕编码**（如 `eia_608`）：判 `unsupported` 明确报错，不猜不降级。
- **所有结局都写 `manifest.json`**（含 `unsupported` / `extract_failed`），路由结论本身即交付物，脚本据此决定下一步。
- **退出码**：`0` 抽出/需 ASR ／ `1` IO 或 ffprobe/ffmpeg 失败 ／ `2` 图形字幕或未知编码（`unsupported`）。

**验收**：

- **AC-1** 对含文本字幕流的 MKV/MP4，抽取结果与源字幕流**逐条一致（100%）**
- **AC-2** 路由判定在样本集（§6）上 **100% 正确**，含 PGS、forced 轨、无字幕流三种边界
- **AC-3** 图形字幕流输入必须**明确报错**，不得输出空字幕或静默转 ASR

> 实测依据：内封字幕抽取 `ffmpeg -map 0:s:0` **耗时 < 1 秒、逐条 100% 一致**；AR 路线成本约等于 0，故降级为薄层中的一个分支。

### FR-2 字幕文件矩阵 + CPS 校验

**输入**：源语言 SRT + 目标语言 SRT（由底座 `/translate_srt` 或 DeepSeek 产出）
**行为**：

1. 导出 5 种格式：**单语 SRT**（英文）、**双语 SRT**（原文一行 + 译文一行）、**ASS**（带基础样式）、**VTT**、**TXT**
2. 结构校验（硬约束）：
   - 条数一致
   - 时间轴逐条一致（容差 0）
   - 无空译、无漏译
3. 阅读性校验（报出、不自动改）：
   - **CPS 上限**：英文 ≤ 20 字符/秒，中文 ≤ 9 字符/秒（可配置）
   - **行宽**：英文 ≤ 42 字符/行，中文 ≤ 16 字/行（可配置）
   - 单条最多 2 行
4. 违规项写入 `report.json`：cue 号、指标、实测值、阈值。**不自动改时间轴、不自动删条**——由人工决定。

**实现补充（M1 已定，不再重复讨论）**：

- **计数口径**：英文计空格、不计换行与首尾空白；中文不计空白（标点算 1 字）。报告 message 里给出「字符数 / 时长」，可人工审计。
- **条数不一致**：只报 1 条 error、**跳过逐条比对**（索引已错位，逐条比会刷出上百条噪声）、**不导出任何字幕文件**（错位的双语比没有更危险）。
- **退出码**：`0` 通过（允许仅 warning）／`1` 用法或解析失败／`2` 结构校验不通过。
- **ASS** 用厘秒且**向下取整**（避免 10ms 叠压）；字体 `Microsoft YaHei`（Arial 无中文字形，烧录会变方框）。


**验收**：

- **AC-4** 5 种格式均可被 ffmpeg / VLC / Subtitle Edit 正常解析
- **AC-5** 构造的违规样本（超 CPS、超行宽、空译、条数不符）**100% 被报出，零漏报**
- **AC-6** 双语 SRT 的原文与译文在时间轴上**逐条对应**（同一 cue 内两行）

> 实测依据：微软免费翻译 6 条均保持条数/时间轴，平均 **CPS 15.8**（12.7–17.9），故 CPS 上限 20 是合理阈值；PRD v1.0 只约束"每行字数"不够。

### FR-3 配音编排（并发 / 重试 / 时长校验）

**前提**：底座 `/tts` 是否并发需在 M0 验证。**若不并发 → 由本层做并发调度**（建议 N=3–5，可配置）。

**前置（M0 实测后新增，必须做）**：**ASR 句级合并**。Whisper 产出的碎片 cue（常见 2–3 秒一条）若直接拿去翻译+配音，译文时长必然撑爆槽位。实测对比（同一段 41 秒中文语音）：

| 处理方式 | cue 数 | 溢出槽位 | 最大溢出 | 端到端耗时 |
|---|---|---|---|---|
| 不合并 | 10 | **10 / 10** | **+66%** | 80.0s |
| 句级合并后 | 6 | 5 / 6 | +22% | **52.0s** |

合并规则：按句末标点（。！？.!?）切分，单条上限 12 秒，间隔 ≤1s 的相邻碎片合并。

**行为**：

1. 逐条调用配音（Edge-TTS 默认音色；可选云端克隆 API），**并发执行**
2. **单条失败重试 2 次**；最终失败的条目只记录、不阻塞其余
3. **时长校验**：每条配音时长 vs 原槽位时长 → 产出 `dub_report.json`（偏移、溢出百分比、超阈值清单）
4. 溢出策略按顺序：`自适应提语速（同音色 +45/+55/+65% 档位）` → `atempo 压缩（≤1.4x）` → `静音段吸收` → `标记人工处理`；**不默认顺延**
5. **配音友好改写**：翻译阶段需控制译文口播长度（LLM 渠道可在提示词里约束）。实测：同一段中文，人工精简译文溢出仅 **3/6、+8%**；免费 MT 的冗长直译使溢出恶化到 **5/6、+22%**——译文越长，越依赖 atempo 硬压，音质越差。**M17 补充**：精简预算取「字幕阅读 CPS」与「配音槽位容量（TTS 实测语速 × 提语速/atempo 余量）」中更严的一个，只在真念不完时才动文本
6. **保留背景音乐**（M6）：`--keep-bgm` 时把原片音轨拆成「人声 / 伴奏」，丢掉原人声、把伴奏与 TTS 混音（配音说话时伴奏自动压低 12dB），再并进成片。**模型不自建**：demucs 只在进程边界调用；分离不可用时按 `auto` 降级为 ffmpeg 相位抵消，并在报告 `warnings` 说明；原片无伴奏必须明说，不得假装保留

**实现补充（M4 已定）**：

- **句级合并**：按句末标点（`。！？.!?…`）切句，英文句点后紧跟数字/字母不切（`3.5`/`U.S.` 不误切）；单条 ≤12s；相邻间隔 ≤1s 才合并；时间轴取"首条开始 → 末条结束"，同一条 cue 内被切开的尾巴从**上一段结束点**起算（否则会与前一条时间轴重叠）。
- **TTS 引擎可插拔**：`EdgeTtsEngine`（子进程 `python -m edge_tts`，用 `--tts-python` 指定装好包的解释器）／`CommandTtsEngine`（`--tts-command` 模板，给云端克隆 API 留插槽）。核心层不引入第三方 import——Edge-TTS 的 `Sec-MS-GEC` 是混淆的自研校验令牌，不重写、只在进程边界调用。
- **溢出策略落地（M4 定，M17 升级）**：`≤ 槽位` → `none`；`> 槽位但 ≤ 可用空间` → `absorb`（借句间静音，不压语速）；
  否则先**提语速重合成**（同一音色换更高档位，`+45/+55/+65%` 逐级、上限 `+80%`，`--no-adaptive-rate` 可关）→ 仍溢出则 `atempo`（上限默认 1.4，`--tempo-limit` 可调）→ 压到上限仍溢出 → `manual` 交人工；**不默认顺延**。
- **配音语速估算**：`tts.speech_cps()` 由实测标定（中文 +30% ≈ 6.0 字/秒、英文 +20% ≈ 18.4 字符/秒），
  `speech_capacity_cps()` 再乘 1.6 的"提语速 + atempo"余量，给翻译层当槽位容量预算。
- **铺轨**：每条配音按自己的槽位起点 PCM 直写（不拼接流水音轨）；视频比字幕长时音轨补到视频长度，否则 `-shortest` 会截短画面。
- **状态**：`ok` / `partial`（有条目失败，其余照常产出，退出码 2）。
- **只合并不拆分**：按句末标点决定"合到哪句为止"，但不把一条 ASR 段落按句子拆开——段落时间轴是真实语音占用时间，拆开只能猜（实测按字数拆分产生 12/48 条零时长，被 `build` 拒绝）。
- **`--tts-rate`**：Edge-TTS 语速（如 `+40%`）。当目标语言天生更长（如 en→zh 播客）时先整体提速，再决定要不要 atempo。
- **ASR 段尾不可信**：不要在底座上开 `--fix_punc`——它给每段补句号，把"半句"伪装成"整句"，翻译只能按半句瞎猜（实测 27 条里 12 条被切断，中文完全读不通）。`merge` 有**续句兜底**：上一条以 `.` 结尾但下一条小写/连接词开头且间隔 ≤1s → 合并并删掉假句号；中文侧无大小写线索，靠间隔判断。
- **合并前拍平 whisper 折行**（按字符宽度折行不是语义换行，否则行数校验全红）；**翻译按整句喂入**（联调工具已按句拆分），避免碎片翻译。

**BGM 保留补充（M6 已实现，`--keep-bgm`）**：

- **三档策略**：`auto`（默认，有 demucs 用 demucs，否则 ffmpeg 相位抵消兜底）/ `separate`（必须 demucs，缺环境报错）/ `center`（`c0-c1` 相位抵消，零下载）/ `duck`（不分离，原声压低当背景，有对白会糊）。
- **混音不是 amix**：配音先 `loudnorm` → 伴奏 `sidechaincompress`（说话时压 12dB，attack 20ms / release 300ms）→ 再整体 `loudnorm` 到 -16 LUFS；`normalize=0` 防止 amix 把配音隐式衰减 6dB。
- **环境**：demucs 4.1.0 + torch 2.2.2+cpu + torchaudio 2.2.2 + numpy 1.26.4，装在 `spike/demucs/.venv`（主包不 import torch）；权重 htdemucs 从 `dl.fbaipublicfiles.com` 下载（本机可达），`TORCH_HOME` 固定在项目内。
- **诚实边界**：素材没有伴奏时报告写"原片几乎没有伴奏（伴奏比原声低 N dB），保留 BGM 无实际效果"；降级原因写进 `warnings`。

**排版补充（en→zh 需要，M4+ 已实现）**：

- 新增 **`build --wrap`**（可选，默认只报不改）：按宽度折行（英文按词、中文按字，优先标点后断、不允许标点独占行）+ **一句一条**（估算 <0.8s 的相邻句才合并，单句超容量降到分句）+ 按长度比例分配时间 + 400ms 最短时长。
- 实测同一段播客：13 条 4–6 行长句 → **57 条 1–2 行**，`line_width` 告警 26 → **1**。（M5 又修掉时序/专名/极端短条问题，最终 49 条、`line_width`/`line_count` 0，见 FR-5）
- **CPS 无法靠切条降低**（字数/时长不变），只能精简译文（condense）或延长显示时间；报告如实列出。

**验收**：

- **AC-7** 100 条字幕的配音任务端到端 ≤ 5 分钟（并发 6；本机实测 6 条并发 12.9s，推算 100 条约 1–3 分钟）
- **AC-8** 配音时长报告覆盖率 100%，溢出 > 10% 的条目 **100% 列出**；报告同时给出**播放时长**（atenpo 之后）与
  `fits_room`（是否落在"本条到下一条"的可用时间内），M17 起 `rate_escalated` / `rate_ladder` 可查
- **AC-9** 单条配音失败不影响其余条目，最终失败清单完整
- **AC-13** 句级合并后 cue 数与人工句级标注一致（±10%）；对样本集，合并后溢出条数占比 **< 80%**（本样本不合并 100% → 合并后 83%）
- **AC-14** 成品视频可正常播放（h264 + aac），时长与源视频偏差 ≤ 0.5s
- **AC-21** `--keep-bgm` 成片音轨同时含配音与原片伴奏；配音说话时伴奏被压低（默认 12dB 侧链）且可配置，成片响度统一 -16 LUFS；分离不可用时按 `auto` 降级并在 `dub_report.json` 写明；**原片无伴奏必须明说**（实测：带 BGM 素材伴奏 RMS 1274/原声 3560，混音静音段仍有背景；纯口播素材伴奏 RMS 仅 29，报告如实标注）

> 实测依据：6 条译文配 Edge-TTS 后有 **3 条超出原槽位，最大 +8%** —— 时间适配是真实问题，`atempo ≤1.3x` 够用。另：云 TTS 是**逐条一次网络请求**（本环境 11s/条，几乎全是握手延迟），串行处理 100 条即不可接受，故必须有并发。

### FR-4 AIGC 标识（合规必需）

**显式标识**：

1. 输出视频**起始画面叠加显著文字标识**（默认右上角"AI 生成"，≥3 秒，可配位置/文案/时长）
2. 导出/下载的文件本身自带该标识（不得只在外壳页面提示）

**隐式标识**（写入 MP4 文件元数据）：

| 字段 | 内容 |
|---|---|
| `comment` | 生成合成属性（如"AI 配音 + AI 翻译"） |
| `artist` / `copyright` | 服务提供者名称/编码（可配置） |
| `content_id` | 内容编号（UUID，每次生成唯一） |

**行为约束**：

1. 默认**开启**；
2. 仅在"仅自用不发布"模式下允许关闭，且关闭时**必须写日志留痕**；
3. **不提供**可通过命令行参数移除标识的途径（《人工智能生成合成内容标识办法》第十条禁止删除/篡改标识）。

**实现补充（M3 已定）**：

- **显式标识**：`drawtext` + `textfile=`（文案作为文件读入，冒号/逗号/方括号/百分号都不会被过滤器转义吃掉）；字号按 `画面高度 × 5%` 自适应（720p→36px、1080p→54px），白字 + 半透明黑底保证任何画面上可读；**时长 < 3 秒直接拒绝**。
- **隐式标识**：MP4 必须加 `-movflags +faststart+use_metadata_tags`——不加时 `content_id` 会被 muxer **静默丢弃**（`comment`/`artist`/`copyright` 却正常，极难发现）。
- **自动核验**（不过就退出码 2，不假装成功）：① 产物 `ffprobe -show_format` 回读 4 个字段逐项比对；② 同一时间点分别从源片与产物抽帧转灰度，统计"亮度差 > 40"的像素占比——标识段应明显 > 0、标识结束后应回到 0。
- **自用模式是唯一关闭途径**：`--self-use`，且必须写 `self_use_notice.json` 留痕（时间、输入 sha256、法条引用、禁止发布提示）；无 `--no-label`/`--strip-metadata` 类参数。
- **字体**：自动探测（雅黑→雅黑粗→黑体→宋体），找不到明确报错。注：字体路径不存在时 ffmpeg 不是报错而是**访问违例崩溃**，必须先自己校验。

**验收**：

- **AC-10** 输出视频起始 3 秒内可见显式标识（抽帧核验）
- **AC-11** `ffprobe -show_format` 可读出全部隐式标识字段
- **AC-12** 除"自用模式"外无任何参数能移除标识

> 依据：《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号）**2025-09-01 已施行**，第四条要求视频起始画面显著显式标识、导出文件须含标识；第五条要求文件元数据写入隐式标识；第六条平台会核验元数据。

### FR-5 识别与翻译编排（M5 新增，对齐收费软件）

> 定位：**引擎不自建**（ASR 用 faster-whisper，MT 走外部渠道），本层只做收费软件在
> "识别/翻译"这两层的**编排与质量手段**。触发原因：用户要求"对齐收费软件，除非成本特别大"。

**行为**：

1. **ASR 直连**（`cuesmith asr`）：拿**词级时间戳**、**热词偏置**（`--hotwords` /
   `--hotwords-file`，可直接复用术语表）、VAD 静音过滤；按句末标点/长停顿/超长/超宽切条，
   不按固定秒数硬切；产出 `source.srt` + `words.json` + `asr.json`。
   **模型只在底座 venv 里跑**（`--asr-python` 自动发现），主包不引入 ctranslate2。
2. **翻译编排**（`cuesmith translate`）：
   - 渠道：`microsoft`（免费端点，默认）/ `openai`（OpenAI 兼容）/ `command`（外部命令模板）
     / `echo`（仅离线测试）；
   - **源文清洗**（ASR 残留的 `,and`、标点前空格、句首小写、独立 `i`）；
   - **整句化**：半句不翻，假句号（下句小写开头）并回；
   - **段落上下文**：相邻 cue 编段（≤4 条 / ≤480 字 / 间隔 ≤1.5s）整段翻译；
   - **一句对一句对齐**：整段的句子放进同一个请求（模型有上下文），返回同样多的句子后按"句子属于哪条 cue"精确拼回；
   - **术语表/禁译表**：翻译前 `{{G0}}` 占位保护、翻译后还原指定译法；丢失要报；
   - **译后精简（默认开启，`--no-condense` 关闭）**：目标 CPS 超限时 `rule`（只删口头禅）→
     `trim`（截分句，丢信息但报告列出）→ `llm`（重写）；带术语译法的分句**不许截**，
     删不动就宁可超限；`translate.json` 的 `needs_review` 逐条列出被改写的 cue；
   - **LLM 深度上下文**：术语占位符附带"原文→应输出"对照、按 cue 时长给每行字数预算；
     返回条数不符时先强调条数重试、再对半拆批，不整批失败；`--llm-review` 支持多轮审校
     （默��� 2 轮，零改动即收敛），逐条 `before/after` 留痕；
   - `translate.json` 报 CPS（精简前后）、超限条数、术语丢失、回退条数、耗时、token 账单。
3. **排版时序修正**（`build --wrap` 增强）：时间分配按译文所需时长（`字数/目标CPS`）
   分配，原文只提供"这段语音占多久"的外框；中文折行不拆拉丁专名、标点不独占行、不因合并标点撑破行宽。

**实现补充（M5 已定）**：

- 占位符只用 `{{G0}}` 一种形态（实测 `[[1]]` 会被微软改成 `[[[1]]`，PUA 字符会被换成空格）。
- 上下文翻译用"整段句子数组"：一个请求带整段上下文、返回同样多的句子，再按句子归属精确拼回 cue；单条译文过短时回退逐条翻译，报告 `fallback_cues` 计数。
- 免费端点实测约 **10s/请求**（2 分钟素材 8 段共 79s）；LLM 渠道（DeepSeek）131s / 2454 token，`translate.json` 记录 calls/tokens。
- 俚语/专名：术语表命中时翻译前已被占位，机翻不会改错；丢失占位符会在报告 `placeholder_lost` 计数并告警。

**验收**：

- **AC-15** `asr` 产物含每个词的起止时间；切条只发生在句末/长停顿/超长/超宽处，碎片会被合并

| **底座是否并发未知** | 配音耗时爆炸 | M0 实测：Edge-TTS 串行 11.2s/条，6 并发总耗时从 66.9s 降到 12.9s（**5.2x**）。FR-3 要求并发 6，不再依赖底座 |
| **依赖最新版在本机崩溃**（已实测坐实） | ASR / VAD 直接不可用 | `ctranslate2` **4.8.0 与 4.8.3 均访问违例崩溃**（py3.10 与 py3.11、int8/float32、1/4 线程、强制 AVX2/GENERIC/AVX 全复现），4.5.0 / 4.4.0 / 4.3.1 正常；`onnxruntime` **1.31.0 崩溃、1.23.2 DLL 初始化失败**，1.20.1 / 1.18.1 正常。**pyVideoTrans 官方钉 `ctranslate2==4.8`** → **预打包版实测不可用**（GUI 能启动，一跑 ASR 必崩）。对策：**用源码版并 pin `ctranslate2==4.5.0` + `onnxruntime==1.20.1`**（本 M0 即按此跑通） |
| **ASR 碎片句导致配音全溢出** | 配音严重超时 | 新增 FR-3 前置「句级合并」；实测溢出从 10/10（+66%）降到 5/6（+22%） |
| 云 TTS 网络不稳/限流 | 配音失败 | 并发 + 重试 + 失败清单 + 本地缓存已合成音频 |
| 模型下载被墙（HF 不可达） | 首次使用失败 | 走 ModelScope 或手动下载；文档给出步骤 |
| 本机 ctranslate2/onnxruntime 崩溃（沙箱内已复现） | ASR/说话人分离不可用 | M0 在真机复测；若真崩则改用 openai-whisper 通道 |
| 声音克隆走云端 API | 按量付费、音色效果待验 | 供应商待定；先用免费通用音色兜底，不阻塞一期 |
| 译文时长溢出 | 配音错位 | FR-3 时长报告 + 自适应提语速（+45/55/65%）+ atempo ≤1.4x（M17 实测：英文 10min 播客转中文，转人工 **10 → 1**、85/86 条不出可用时间） |

## 9. 明确不做（Out of Scope，含理由）

| 不做 | 理由 |
|---|---|
| 硬字幕 OCR（v1.0 的 FR-2B） | 仅处理自有素材时几乎用不上；唯一的高成本模块 |
| 本地声音克隆（CosyVoice2/F5-TTS） | 无 CUDA，不可行；改走云端 API 可选 |
| 唇形同步（Wav2Lip/MuseTalk） | 无 GPU；Wav2Lip 官方**禁止商用**；效果不及商业产品 |
| ASR 模型 / 说话人分离 | **模型不自建**：M5 直接调用 faster-whisper（只跑在底座 venv，进程边界隔离），自己做词级时间戳、热词偏置、语义切条。**说话人分离已做（M11）**：sherpa-onnx（pyannote segmentation-3.0 + 3D-Speaker/NeMo 声纹，ONNX/CPU，模型约 67MB 本地、无需 HF token），仍属"调用外部模型、只做编排"；M16 实测 4 人样本 `--speakers 4` 识别 4 人/10 段、端到端 4 音色配音 8/8。**更大 ASR 模型不随包分发**：medium 权重 1.46GB（已从 ModelScope 下到 `spike/whisper-models/faster-whisper-medium`，`--model medium` 即用）；large-v3 未评估（3GB、CPU 更慢）。分发时由用户按 `M7` 文档命令自行下载，不进仓库 |
| 翻译引擎 | **不自建**：M5 编排微软免费端点 / OpenAI 兼容 / 外部命令三类渠道，自己做源文清洗、整句化、段落上下文、术语表、译后精简。模型/接口本身仍是外部渠道 |
| BGM 人声分离 | **已做（M6）**：demucs 权重在 `dl.fbaipublicfiles.com`（本机可达，绕过 GitHub 被墙），主包只在进程边界调用；UVR/MDX 多模型方案仍不做（GitHub Releases 下载受阻，demucs 已够用） |
| Web UI / 任务队列 / 历史任务 | 底座 GUI + CLI + REST API 已覆盖 |
| 字幕校对编辑器 | 底座有分阶段人工校对 |
| 多语言（除中/英） | 一期只做 **zh↔en 双向**（`LANG_PROFILES` 仅 zh/en），ja/ko/fr 等未支持 |
| 计费 / 多租户 / 移动 App | 非目标 |
| 视频链接下载（B站/YouTube） | 版权与 ToS 风险；与"自有素材"边界冲突 |
