# 代码规范

> 这份文档是**本仓库代码的唯一权威约定**。人和 AI 助手写新代码时按它办；改旧代码时
> "碰到就顺手对齐"，但不要在同一次提交里顺手重排无关代码（审查会被淹没）。
>
> 文档与代码冲突时：**先改代码，或先改这份文档**，不许两套并行。改动规范本身要单独
> 提交，并在提交信息里写清"为什么现在改"。
>
> 能做机器校验的条目，都落在 [`tests/test_structure.py`](../tests/test_structure.py)
> 里，跑一次就知道有没有走样。

## 0. 三条底层原则

后面所有条款都是这三条的展开，冲突时按这三条判断：

1. **一个接缝只有一个入口**。跑外部工具、找解释器、起 worker、写报告，各自只有一处实现。
   出现第二处，就是下一个 bug 的温床（历史上 4 个模块各拼一遍 ffmpeg 前缀，最终一起出错）。
2. **状态要集中，不要靠局部变量接力**。一个函数里跨阶段传递的变量超过 3 个，就该有
   一个状态对象；超过 5 个还各自被就地覆盖，就没法证明"改这里没动那里"。
3. **行为变化要有证据**。重构必须有等价性对照（§7.6）；新功能必须有边界用例。
   "我看了一遍觉得没问题"不算证据。

## 1. 包结构

### 1.1 分层（依赖只能单向向下）

| 层 | 模块 | 可以依赖 |
|---|---|---|
| **L0 基础**（零内部依赖） | `srt` `textutil` `langs` `glossary` `media` `interpreters` `worker_protocol` `cost` `history` `atomic` | 标准库 |
| **L1 领域能力** | `validate` `clean` `condense` `export` `report` `merge` `probe` `asr` `diarize` `translate` `burn` `mark` `tts` `localtts` `bgm` | L0 + 同级（**必须无环**） |
| **L2 编排与入口** | `dub` `pipeline` `layout` `matrix` `voices` `cli` `gui` | L1 / L0 |
| **worker 子进程** | `asr_worker` `diarize_worker` `tts_worker` | 标准库 + `worker_protocol`（**禁止依赖领域模块**） |

规则：

- 上层可以依赖下层，**下层不许依赖上层**（`report` 不许 import `pipeline`）。
- 同级之间允许互相引用，但**不许成环**（`test_structure.py` 会算）。
- 新增一条跨层依赖，要么本来就该有，要么说明分层表画错了 —— 无论哪种，都要在同一次
  提交里更新 §1.1 的表格和 `test_structure.py` 的 `EXPECTED_EDGES`，让它出现在 diff 里。

### 1.2 三条硬边界

1. **主包零第三方运行时依赖**：`submatrix/` 只允许标准库 + 调用外部 `ffmpeg`/`ffprobe`。
   需要 numpy/torch/gradio 一类的东西，一律放到 `spike/*/.venv` 里，通过子进程调用。
   `pyproject.toml` 的 `dependencies = []` 是这条边界的执行器。
2. **重依赖只在 worker 里 import**：模型库的 import 必须发生在 `*_worker.py`（跑在
   独立解释器的子进程里）。主进程只认 `worker_protocol.py` 的 JSON 行协议，
   **不许 `import` 模型库**，连 `try: import` 探测都不行（探测走 `interpreters.py`）。
3. **外部工具只走三个接缝**：

   | 需求 | 唯一入口 | 不许 |
   |---|---|---|
   | 跑 ffmpeg / ffprobe | `media.run_ffmpeg` / `run_ffprobe` / `ffprobe_json` / `exec_tool` | 自己拼命令、自己 `shutil.which("ffmpeg")` |
   | 找一个装了某包的解释器 | `interpreters.resolve` / `runner_probe` / `subprocess_probe` | 在模块里写 `shutil.which` + 猜路径 |
   | 起一个常驻 worker | `worker_protocol` 的会话对象 | 自己拼 JSON 行协议 |

   **例外（明确允许自管子进程）**：进程生命周期本身是业务逻辑的地方 ——
   `localtts`（常驻 TTS worker 的重启/超时）、`gui`（跑 pipeline 子进程、终止进程树）、
   `tts`/`translate` 的 `command` 渠道（用户提供命令模板）。这些必须显式给超时，
   `encoding="utf-8", errors="replace"`，并在退出时清理。

### 1.3 新模块放哪

```
是不是"跟外部进程/模型打交道"？
├─ 是，常驻且要协议 → 新 worker 模块（*_worker.py）+ 主包侧的薄客户端（loca*lt* 那种）
├─ 是，一次性调用 → L1，但工具调用必须走 §1.2 的接缝
└─ 否
   ├─ 只做纯函数变换（文本、时间轴、布局、评分） → L0 或 L1 的纯模块
   ├─ 串起多个阶段、写产物、出报告 → L1（单阶段）或 L2（多阶段编排）
   └─ 面向用户（命令行/表单） → L2（`cli` / `gui`），逻辑要留在下层，入口只做参数与展示
```

判断标准：**入口层不许有业务算法**。`cli.py` 只做参数解析、调用、打印汇总；算法在 `layout`/`validate`/`cost`。

## 2. 编排层的标准形状

一次"跑一条链路"的模块（`pipeline`、`dub`、`translate`、`matrix`）按同一个骨架写：

```python
def run_xxx(options: XxxOptions) -> XxxResult:
    """一句话说明产物与失败方式。"""
    session = _XxxSession.start(options)   # 校验 + 读输入 + 建渠道（一次性准备）
    _prepare(session)                       # 各阶段：一个函数一件事
    _do_main(session)
    _finalize(session)
    return _write_outputs(session)          # 落盘、报告、返回命令行契约
```

### 2.1 阶段表 vs 阶段函数

- **多阶段流水线**（≥3 段、可单独跳过、要写 `pipeline.json`）：用阶段表 `_STEPS` +
  `_stage_xxx(options, run) -> 结果` 的形式，别把 `if/elif` 串在主函数里。
- **单次编排**（`dub`、`translate`）：用状态对象 + 顺序调用的阶段函数，同样不许回到
  "一个大函数从头写到尾"。

### 2.2 什么时候必须建状态对象

满足任一条就必须建（`@dataclass(slots=True)`，私有、以下划线开头）：

- 跨阶段传递的变量 ≥ 3 个；
- 同一个变量被两个以上阶段就地覆盖（典型：`texts` 先翻译、再被审校覆盖、再被精简覆盖）；
- 需要按条目记状态（每条 cue 的 audio/duration/error/attempts）—— 这种一律用**对象或
  小 dataclass**，不许用多张 key 相同的平行 dict（改一个字段要同步改 5 处，漏一处就是
  静默错值）。

状态对象只放**数据**；行为放阶段函数。`_Outcome` 那类"给报告用的结论快照"同样只读。

### 2.3 函数长度

| 长度 | 要求 |
|---|---|
| ≤ 60 行 | 正常 |
| 61–150 行 | 允许，但必须能一句话说清它在做哪一件事；否则先拆状态对象 |
| > 150 行 | **默认拆**。要留着就得进 §10 的豁免名单并写理由 |

**豁免（行数不作为拆分依据）**：纯声明式代码 —— 报告字典字面量（`_translate_report`、
`_build_report`）、UI 控件装配（`build_app`）、CLI 参数表（`_add_*_args`）。
这些的行数来自"字段/控件/参数有多少"，拆成十个 helper 只会让人跳来跳去。

## 3. 数据与类型

- **选项对象**：`@dataclass(frozen=True, slots=True)`，字段全部带默认值（除路径/必填），
  新字段加在末尾并写注释说明"进不进缓存键"。`PipelineOptions` 的 docstring 里有
  "新增一个参数要动哪几处"的清单，加参数前先读。
- **内部状态**：`@dataclass(slots=True)`，私有类名。
- **公开返回值**：`@dataclass(frozen=True, slots=True)`，字段是契约（`TranslateResult` 等）。
- **类型标注**：导出函数（`__all__` 里的）必须标全参数与返回；内部函数鼓励标。
  `Any` 禁用；`object` 只出现在 JSON 边界，并且**取出来就要立刻收窄**成具体类型。
- **报告里的 JSON**：`dict[str, object]` 是入口。取**一段**（dict）时一律用
  `report.section(report, "summary")`（缺段/坏值都得到空 dict），**不要**再写
  `(report.get("x") or {}).get("y")`。**禁止 `# type: ignore`**（基线已是 0 处，见 §10.3）：
  JSON 里的数字先 `isinstance` 收窄再 `int()/float()`，嵌套响应走 `cast` 链。
- `__all__`：除 `__init__.py` / `__main__.py` / `*_worker.py` 外每个模块都要有，列**对外
  契约**，不是列全部函数。

## 4. 错误处理

- **一域一异常类**：`XxxError(Exception)`，模块内 `raise XxxError("说人话的原因")`。
  不许抛 `ValueError` 让上层猜（跨模块边界时包装成领域异常，`raise ... from None`）。
- **错误消息模板**：`现象 + 下一步`。反例："无法读取"；正例："输入字幕不存在：
  {path}（先用 probe 子命令确认路径）"。
- **禁止**：
  - 裸 `except:`；
  - `except Exception: pass`（吞掉异常后继续输出错误结果，比崩掉更糟）；
  - 为了"跑通"而把失败当成功（`status`、`exit_code`、报告里的 `errors` 必须一致）。
- `except Exception:` **只在**"失败不影响产物正确性"的收尾路径（清理临时文件、读配置
  缓存失败退回默认）使用，并且**必须带行内注释说明为什么安全**；`test_structure.py` 会
  检查注释存在。
- **内部不变量**违反用 `"内部错误：…"` 前缀，表示"这是 bug，不是用户输入问题"。
- **退出码**：`0` 全部成功 / `1` 用法错误（参数不对）/ `2` 输入或环境不满足（文件不存在、
  缺模型、编码不支持）。有部分失败但产物可用 → `0` 或 `2` 由各命令契约决定，但必须写进
  该命令的 docstring 与测试。

## 5. 缓存与幂等

- 缓存键 = **输入内容 sha256** + **影响输出的一切配置**。路径、时间、耗时、随机数
  **不许**进键。
- 新增一个 CLI 参数时，三选一并写清楚：
  1. 进缓存键（改它会重算）；
  2. **不**进键，但已登记在 §10 的"有意不进键"清单里；
  3. 不适用（纯展示参数）。
  默认必须是 1 —— 不写就是 bug（历史上 `--force`、`--regenerate-tts` 都漏过）。
- 下游产物依赖上游字幕时，键里带**上游文件内容**的 sha256，而不是"上游跑过没有"。
  人工校对上游文件后重跑，必须自动失效。
- 所有产物报告带 `schema_version`；报告键顺序算契约（有等价性测试会逐字节比）。
- **写产物一律用 `submatrix.atomic`**：`atomic.write_json(path, data)`（UTF-8 / 缩进 2 /
  结尾换行 / 临时文件 + `os.replace`）。半截 JSON 比没有文件更坏 —— 它是缓存判据的来源，
  下次会以"产物损坏"的形式失败，把排查方向带偏。

## 6. CLI 参数的单一事实来源

- 参数定义只在 `cli.py` 的 `_add_xxx_args(parser, ...)` 里，一个子命令一组；共享参数
  用 `_add_dubbing_args(parser, *, ...)` 这类"带默认值差异"的复用函数。
- `pipeline` 用 `vars(args)` 透传：`_CLI_ONLY_ARGS`（`command`、`stop_after` 等不进
  PipelineOptions）与 `_EXPANDED_ARGS`（`--hotwords` 展开成列表等）必须随新参数同步，
  并有测试（`test_every_pipeline_flag_lands_on_pipeline_options`）兜着。
- **新增一个参数要动的清单**：options dataclass → `_add_*_args` → `_CLI_ONLY_ARGS`/
  `_EXPANDED_ARGS`（如果是 pipeline）→ 缓存键判据 → 报告 `config` → GUI 表单（如果暴露）
  → README 命令速查。少一处就会被"参数加了但没生效"咬到。

## 7. 测试

- 一个模块一个测试文件，命名 `test_<模块>.py`；用例名是**契约描述**
  （`test_uses_next_cue_start_as_room`），不是 `test_case3`。
- 断言**契约**（退出码、报告字段、产物文件、字幕内容），不断言实现细节（内部函数调用次数
  除外——那正是被破坏的契约时）。
- **不联网、不依赖本机状态**：外部引擎一律用假对象注入；真引擎/真素材用例走
  [§7.3](#73-真实素材与耗时用例) 的按需开关。
- 边界优先：空输入、单条、超长、缺字段、坏 JSON、目录不存在、并发顺序、幂等（同参数跑两次）。
- 共用件放 [`tests/support.py`](../tests/support.py)（依赖开关、素材构造）。
  **只放"多处真的是同一件事"**：签名不同就别硬合并（`write_srt` 在 5 个文件里签名各不
  相同，合并只会换来一层间接）。
- 修 bug 的提交必须带一个**会先红后绿**的用例；只改代码不补测试的修复视为未完成。

### 7.3 真实素材与耗时用例

- 默认**不跑**：放在 `tests/test_real_sample.py` 一类文件里，用环境变量开关
  （`SUBMATRIX_REAL_VIDEO` / `SUBMATRIX_REAL_OUT` / `SUBMATRIX_REAL_E2E`），耗时用例打
  `@pytest.mark.slow`。
- 每条 skip 必须给 `reason=`，并且说明**怎么开**（`pytest -rs` 直接看到）。

### 7.6 重构的等价性证据

行为中立的拆分（大函数拆阶段、模块搬家、去重）**必须**提供：

1. 改动前实现的副本（`work/_scratch/xxx_before.py`，以 `submatrix.xxx_before` 加载）；
2. 一份对照矩阵：覆盖所有分支（上下文策略、并发、回退、错误路径）；
3. 比对**全部输出**：返回值、产物文件字节、报告全部键值（含键顺序）、异常类型与措辞；
4. **变异验证**：故意改坏新实现几处，确认基线能抓到；抓不到的变异要记录原因（说明是
   真等价，还是覆盖有洞——两者都要说清楚，不许含糊过去）。

模板见 `work/_scratch/eq_translate.py` + `mutate_translate.py`。

## 8. 文档

- 除仓库根的这几个文件外，**所有文档放 `docs/`**：`README.md`（入口/速查/索引）、
  `AGENTS.md`（AI 协作入口）、`CONTRIBUTING.md`（贡献指南）、`CHANGELOG.md`（变更记录）、
  `LICENSE`。
- **同一个数字只写一处**（测试数、性能数字），别处引用"见 §x"。两处数字迟早对不上
  （README 里曾经同时存在 751 和 838）。
- **历史记录里的数字不是现状**：里程碑/优化说明里的"751 passed"是当时实测值。写这种
  记录时要么带日期，要么注明"当时值"；对外承诺的现状只在 README §3.5 维护一处。
- 实现说明固定小节：做了什么 / 怎么验的（命令与数字）/ 踩了什么坑 / 复跑命令 / 已知限制。
- 代码里的注释回答**为什么**，不回答**是什么**（`# i += 1  # 加一` 是噪声）。
  非显然的取舍要留："这里故意不 X，因为 Y（见某次实测）"。

## 9. 提交

- 标题：`type(scope): 中文摘要`。`type` ∈ `feat` `fix` `refactor` `perf` `test` `docs` `chore`。
- 正文四段（按需裁剪，但**为什么**与**怎么验**不能省）：

  ```
  为什么：原来的问题（谁说它是个问题）
  改了什么：一到三条
  怎么验的：命令 + 实际结果（写数字，不写"应该没问题"）
  有意不做：明确排除的东西 + 理由
  ```

- 一次提交一件事。重构与行为变更**分开提交**；机械重排（格式化、换行、搬文件）单独一个提交。

## 10. 机器校验与已知欠债

### 10.1 提交前必跑

```powershell
python -m pytest -q                     # 全量（含 tests/test_structure.py）
python -m ruff check submatrix tests     # 必须 0（E4/E7/E9/F/I/UP）
```

`tests/test_structure.py` 检查的是"结构约定"，不是风格口味：分层边表、无环、
`__all__`、库模块不许 `print`、裸 `except`、函数长度豁免名单、`type: ignore` 不许增长。

### 10.2 长度豁免名单（与 `tests/test_structure.py` 的 `LENGTH_OVERRIDES` 一一对应）

**声明式 —— 行数来自"字段/控件/参数有多少"，不拆**（拆开只会让人来回跳）：

- `gui:build_app`（Gradio 控件装配）
- `dub:_build_report`（报告字典字面量）
- `cli:_add_pipeline_args`（参数表）

**入口脚本 —— 拆了收益最低**：

- `diarize_worker:main` 160 行：一个"读 argv → 跑模型 → 写 JSON"的 worker 入口，
  跑在独立解释器里、真跑要 sherpa 模型，连等价性基线都只能靠伪造模型对象；
  拆它不会让任何调用方变清楚。

（曾经在这份名单里、现已拆掉的：`pipeline:_stage_diarize` 159→45、`asr:run_asr`
168→10、`mark:run_mark` 192→17、`burn:run_burn` 171→9、`diarize:run_diarize`
327→12。每个都是"状态对象 + 阶段函数"，并且各自带等价性基线 + 变异验证。）

150 行以内的（如 `_translate_report` 134、`_add_dubbing_args` 98）不需要登记。
加一个名字进这份名单，等于**公开宣布欠着**，请在提交信息里写清理由。

### 10.3 已知欠债（不是"已规范"，是"知道欠着"）

| 欠债 | 现状 | 计划 |
|---|---|---|

### 10.4 有意不进缓存键的参数（登记在这里，新增要写理由）

| 参数 | 为什么不进键 |
|---|---|
| `--local-tts-speed` | 只影响本地 TTS 的语速参数，产物内容指纹已经覆盖（音色 + 文本 + 引擎），且它变化必然伴随重新合成 |

| `--out-name` / 输出路径 | 路径不是内容 |
| `--verbose` / `--quiet` 一类展示参数 | 不影响产物 |
