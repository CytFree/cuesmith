## 2. 用法

```powershell
# 1) 句级合并（ASR 碎片 → 句子）
python -m cuesmith merge --src asr.srt --out work\task\merge

# 2) 配音（默认 Edge-TTS；--tts-python 指向已装 edge-tts 的解释器）
python -m cuesmith dub --srt en.srt --video 成品.mp4 --out work\task\dub `
  --voice en-US-AriaNeural --concurrency 6 --retries 2 --tempo-limit 1.3 `
  --tts-python "spike\pyvideotrans\.venv\Scripts\python.exe"

# 3) 一键回归
python tools/run_samples.py --out work\regression
```

| 产物 | 内容 |
|---|---|
| `merged.srt` + `merge.json` | 句级字幕 + 合并前后条数 |
| `dubbed.wav` | 按槽位铺好的配音音轨（24kHz/16bit/单声道） |
| `dubbed.mp4` | 可选：并进视频（h264 copy + aac） |

## 3. 关键决定

1. **只合并不拆分**：按句末标点（`。！？.!?…`）决定"合到哪句为止"，但**不把一条 ASR cue 按句子拆开**——
   ASR 段落的时间轴是这段语音真实占用的时间，拆开只能靠猜（按字数比例），实测在英文播客上把 27 条拆成 48 条、
   其中 12 条零时长被 `build` 拒绝。单条 ≤12s、相邻间隔 ≤1s 才合并；多句的段落保持整条（字幕显示为多行）。
2. **TTS 引擎可插拔**，不硬编码云服务：`EdgeTtsEngine` 调 `python -m edge_tts` 子进程；`CommandTtsEngine` 接任意命令模板（`{text_file}` / `{out}`），给云端克隆 API 留插槽。
   **为什么不用纯标准库重写 Edge-TTS**：当前 `Sec-MS-GEC` 令牌是一套高度混淆的自研校验（CS64 + 定制 SHA-256），跟着实现既不可维护也不该做——所以核心层不引入 import 依赖，改为子进程边界。
3. **并发 + 重试 + 不阻塞**（AC-7 / AC-9）：`ThreadPoolExecutor(max_workers=concurrency)`，每条独立重试（默认 2 次，最多 3 次尝试）；最终失败**只记录**，其余条目照常产出，状态 `partial` + 退出码 2。
4. **溢出三级策略**（AC-8）：`audio ≤ slot` → `none`；`1 < ratio ≤ 1.3` → `atempo`（按实测比例变速）；`ratio > 1.3` → 压到 1.3 后仍溢出 → `manual` 交人工。**不默认顺延**（顺延会让后面全部错位）；溢出的部分自然落进下一条之前的静音（"静音段吸收"）。
5. **按槽位铺轨**：把每条配音解码成 PCM，直接按它自己的 `start_ms` 写进整条音轨（不拼接成流水音轨）。这样每条都对着自己的时间轴，空缺/溢出在波形上一目了然。
6. **音轨补到视频长度**：视频比字幕长时先把音轨补到视频长度，否则 `-shortest` 会把画面截短（实测会丢 0.78s 画面）。
7. **回归用占位引擎**（ffmpeg 生成 1.5s 正弦）：回归要的是流水线机制可复跑，不依赖网络与音色质量；真引擎数据单独实测（见 §4.2/4.3）。

### 4.9 质量诊断：中文"读不通"的根因与修复

用户通读后指出这批中英字幕"意思很不通顺"。逐条比对 27 条的结论：**主要不是翻译引擎不准，而是句子被从中间切断了**。

| 问题 | 规模 | 例子 |
|---|---|---|
| ASR 段尾被 `--fix_punc` 强加句号 → 半句被伪装成整句 | 27 条里约 **12 条是半句** | en `...and it could.` / `suggest to you.`；zh "而且它本可以做到。" / "向你提出建议。" |
| 翻译按半句独立翻，只能瞎猜上下文 | 同上 | "研究。" "回答，你赞成吗？" "右？" "模型挑选者" "去探索学校" |
| whisper 的**按字符折行**被当成语义换行带进字幕 | 全部 27 条 `line_count` 告警 | 每条 3–5 行 |
| 真正的 ASR 词错（次要） | 3 处 | "Astra"(疑)、"With thoughts"(幻觉)、"using…using" 重复 |

**修复（三处，两个方向通用）**：
1. **不要在底座上开 `--fix_punc`**——原始 ASR 段尾没有句号，本身就是"这句还没说完"的信号；
2. `merge` 增加**续句兜底**：上一条以 `.` 结尾、但下一条以**小写字母/连接词**开头且间隔 ≤1s → 合并并删掉那个假句号；
   同时**拍平 whisper 折行**（`_flatten`）；
3. 翻译工具改为**先切整句再翻**（一条 cue 内的句子分别翻译后拼回），并清理 `,and`、句首小写等排版噪声。

**效果（同一 2 分钟素材）**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| cue 数 | 27（约 12 条半句） | **13 条整句** |
| 中文可读性 | 半句拼接、多处不知所云 | 成句；明显错译从 ~7 处降到 ~3 处 |
| `build` 警告 | **64**（cps 22 / line_count 28 / line_width 14） | **32**（cps 6 / line_width 26；line_count **0**） |
| 残留 | — | 行宽 26 处（需要"自动断行"，FR-2 只报不改）；3 处 ASR 词错（需更大模型或人工校对） |

> 同一个坑在 **zh→en** 方向同样存在：只要 ASR 段尾被补了句号，翻译就会按半句走。所以"关掉 fix_punc + 续句兜底 + 整句翻译"是双向通用的修复，中文侧没有大小写线索时靠间隔（≤1s）判断。

### 4.10 en→zh 排版层（`build --wrap`）

收费字幕软件（EZTitles / Ooona / Subtitle Edit）的招牌功能之一。我们按同样的规则实现：

1. **折行**：英文按词、中文按字，优先在标点后断，且不允许"标点独占一行"；
2. **切条**：默认**一句一条**（字幕理想粒度），只有"按比例估出来 <0.8s"的相邻句才合并；单句超过容量才降级到分句/词字切分；
3. **时间分配**：按两侧中较长的一侧长度比例分配，保证首尾时间不变、条间无缝隙；
4. **最短时长保护**：切得太碎没法读（400ms 下限）。

同一段 2 分钟播客（en→zh）实测：

| 指标 | 排版前 | `--wrap` 后 |
|---|---|---|
| 条数 | 13（每条 4–6 行长句，屏幕上根本放不下） | **57**（平均 2.1s，1–2 行） |
| `line_width` 告警 | 26 | **1** |
| `line_count` 告警 | 0（已拍平） | 0 |
| CPS 告警 | 6 | 50（**不是变差**：源语语速约 23.7 CPS，切成 2 秒条后每条的 CPS 都被显式暴露出来） |

> **CPS 不能靠切条解决**（我一开始以为可以，验证后否掉）：CPS = 字数/时长，按比例切分时间后每条 CPS 不变。
> 真正的解法只有两条：**精简译文**（行业叫 condense，需要 LLM 改写）或**延长显示时间**。本工具如实报出，不假装能自动修。

## 7. 项目收尾：完整链路

四个自建 FR 全部落地，串起来是**一条 5 步链路**，每步都有结构化报告、都可单独重跑：

```
probe ──► merge ──► build ──► dub ──► mark
(FR-1)   (FR-3前置)  (FR-2)   (FR-3)  (FR-4)
  │        │          │        │       │
manifest  merge.json report.json dub_report.json mark.json
```

```powershell
python -m cuesmith probe --src 素材.mkv --out work\t\probe         # 内封字幕？or 需 ASR
python -m cuesmith merge --src asr.srt --out work\t\merge          # 碎片→句子
python -m cuesmith build --src zh.srt --tgt en.srt --out work\t\sub # 5 格式 + CPS 校验
python -m cuesmith dub   --srt en.srt --video 素材.mp4 --out work\t\dub
python -m cuesmith mark  --src work\t\dub\dubbed.mp4 --out work\t\final
```

| 阶段 | 底线（不通过就退出码 2） |
|---|---|
| probe | 图形字幕明确报错、forced 轨跳过、无字幕给 ASR 结论 |
| build | 条数/时间轴/空译/漏译 |
| dub | 有失败条目即 partial |
| mark | 显式标识像素核验 + 隐式元数据回读，任一不过即 verify_failed |

**回归**：`python tools/run_samples.py` —— 11 项检查、67 秒、可重复。
