# 本地 TTS 模型对比评估（2026-11-03）

> **后续（同日）**：本评估已落地为 OPT-11——本地 TTS 已接入为可配置渠道（`--tts-provider local`），
> 并作为 Edge 联网失败时的自动兜底（`--tts-fallback local`，默认开）；默认仍用 Edge。
> 实现与实测见 [OPT11-本地TTS兜底-实现说明.md](OPT11-本地TTS兜底-实现说明.md)。
>
> 问题："本地 TTS 有又小又好的模型吗？"——有，但"小""好""多音色""中文"四个条件不能同时满分。
> 以下全部在本机实测（Ryzen 7 7840H，8C/16T，CPU only），样例 wav 都在 `work/local-tts-eval/`，可用耳朵 A/B。
> 听感是主观项，**这里的"好"只用了两个客观代理**：合成速度（RTF）+ ASR 回读 CER/WER（可懂度/发音错误）。

---

## 1. 结论（先说结果）

| 场景 | 推荐 | 理由 |
|---|---|---|
| **要"小 + 快 + 离线"，英文为主** | **Piper**（每音色 77MB） | 实测 RTF **10–12×**（合成 5.3s 音频只要 0.51s），en 回读 WER **0%**；质量干净但偏平，中文只有 huayan 一个女声 |
| **要"自然度 + 多音色"（含中英）** | **Kokoro-82M multi-lang**（382MB / 54 音色） | 82M 参数、中文 8 音色（4 女 4 男）+ 英文 20+；RTF **2.6–3.2×**；但**中文 v1.0 有发音错误**（见 §3），英文缩写要预处理 |
| **中文+英文、单女声、要稳** | **MeloTTS zh+en**（182MB） | RTF **4.4×**，中英各一句回读 CER 0% / 1 词错；只有一个女声，不能做多说话人 |
| **当前线上（Edge-TTS，云端）** | 保持 | 音色最多（300+）、自然度最好；代价是网络（这也是 OPT-10 刚优化的部分） |

一句话：**"又小又好"最接近的是 Kokoro（82M 参数这个量级里质量第一梯队）**；但它的中文 v1.0 需要挑音色/换 v1.1-zh 模型；
如果只做英文或能接受单一中文女声，**Piper 是性价比之王**（77MB、快 10 倍）。

## 2. 实测数据（同一段文本、同一台 CPU、8 线程）

中文测试句：`今天我们来测试一下本地语音合成，看看速度和自然度怎么样。`（28 字）
英文测试句：`Local text to speech is now fast enough to run on a laptop without a GPU.`

| 模型 | 磁盘 | 说话人 | 中文 RTF | 英文 RTF | 中文 CER* | 英文 WER* |
|---|---|---|---|---|---|---|
| **Piper**（zh_CN-huayan / en_US-amy） | 77.4 MB / 音色 | 1（每模型） | **10.3×** | **11.8×** | **0.0%** | **0.0%** |
| **Kokoro-82M multi-lang** | 382.7 MB（model 326MB + voices 28MB） | **54**（中 8 / 英 20+） | 2.6–3.2× | 2.5–3.2× | 0–30.8%（看音色） | 12.5%（缩写 GPU 被跳过） |
| **MeloTTS zh+en** | 182.4 MB | 1（女声） | **4.4×** | 4.5× | **0.0%** | 12.5%（1 词） |
| Edge-TTS（云端参照） | 0 | 300+ | 网络 | 网络 | 0.0% | 0.0% |

\* **CER/WER 是"把合成音频用 faster-whisper 转回文字"与原文比较**：只反映"发音/可懂度"，
不等于自然度；一句一个样本，仅作粗筛（模型差异见 §3）。

模型加载：Piper 0.3–0.5s；Kokoro 2.0–2.2s；MeloTTS 3.5–4.7s（一次性，dub 进程内复用）。
`speed` 参数：Kokoro 实测 0.85/1.0/1.2/1.4/1.6 → 音频 4.34/3.93/3.43/2.66/2.49s，**线性可调**（对我们的"提语速"逻辑友好）。

## 3. 质量细节（重要，别只看表）

### Kokoro 中文 v1.0 有发音问题

同一句 8 个中文音色回读：

| 音色 | CER | ASR 听到的 |
|---|---|---|
| yunxi（男） | 0.0% | 今天我们来测试一下本地语音合成… |
| yunyang（男） | 0.0% | 同上 |
| xiaobei（女） | 3.8% | …本地语音合成**了**看看…（多字） |
| xiaoxiao（女） | 7.7% | …本地语音**和成语**…（"合成"读错） |
| xiaoyi / yunjian / yunxia | 7.7% | "和成额"/"和成误" |
| xiaoni（女） | 30.8% | "本地运河成涡…宿都和自然都"（严重） |

原因：Kokoro v1.0 的中文靠单字/词表 + 词典（jieba）拼接，**多音字/未登录词容易读错**；
Kokoro 官方后续出了 `v1.1-zh`（中文专门加强），本项目评估只下了 v1.0。
→ 如果走 Kokoro 中文，需要：**换 v1.1-zh 模型 + 逐音色抽检 + 数字/缩写规范化**。

### 英文

- Piper / Edge：`GPU` 都能读对（WER 0%）；
- Kokoro：`GPU` 是 OOV，被词典直接**跳过**（日志有 `OOV word skipped`），导致 WER 12.5%；
  需要文本预处理（缩写、数字转写）——这对字幕配音可接受（我们的译文一般没有裸缩写），但要记录；
- MeloTTS 英文把 `now` 读成 `not`（1 词），整体可用。

### Piper 的短板

- 音质偏"平/机械"，自然度明显不如 Edge/Kokoro（主观，用户可听样例对比）；
- 官方中文音色少（sherpa 发布里就 `zh_CN-huayan-medium` 一个女声），**做不了多说话人**；
  英文音色多（amy/lessac/ryan 等，可另下）。

## 4. 与现有管线怎么接

`dub` 已经支持 `--tts-command` 模板（`{text_file}` / `{out}` / `{voice_id}`），所以**不改核心代码**就能试本地 TTS：

1. 写一个薄 wrapper：`tools/tts_local.py`（跑在装有 sherpa-onnx 的 venv 里），
   `--text-file --out --voice kokoro:47` → 合成 wav；
2. `dub --tts-command "spike\diarization\.venv\Scripts\python.exe tools\tts_local.py --text-file {text_file} --out {out} --voice {voice_id}" --speaker-voices "SPEAKER_00=kokoro:50,SPEAKER_01=kokoro:47"`；
3. 已知限制（当前 `--tts-command` 语义）：
   - **不会自动提语速**（OPT-2 的 adaptive_rate 对外部命令跳过），放不下的条目靠 atempo ≤1.4 兜底；
   - 想用 Kokoro/Melo 的 `speed` 参数做"零 artifact 提速"，需要给模板加 `{speed}` 占位符（小改动，可提）；
4. 性能预估（10min 素材、86 条、TTS 总音频约 5min）：
   - Piper RTF 10× → 单线程 ~30s，4 并发 ~10s；
   - Kokoro RTF 3× → 单线程 ~100s，4 并发 ~25–30s；
   - Melo RTF 4.4× → 单线程 ~68s，4 并发 ~20s；
   - 对比现在 Edge 网络约 **153s**（好窗口），CPU 还有富余（dub 阶段没有别的重活）。

**多音色映射也天然支持**：Kokoro 中文 8 个音色（xiaobei/xiaoni/xiaoxiao/xiaoyi/yunjian/yunxi/yunxia/yunyang）
可以一人一个；英文 20+。Piper 中文只有一个，做多说话人不行（英文可以下多个音色）。

## 6. 关于"时间和质量双好"（补充结论）

严格按"**自然度追平 Edge + CPU 快**"这个标准：**这个体积档里没有**。

- **Piper**：时间满分（RTF 10–12×），可懂度满分（CER/WER 0%），但听感偏平、中文只有单女声
  → "时间好、质量够用"；
- **Kokoro-82M**：最接近"双好"——RTF 2.6–3.2×（已快于实时，10min 素材 4 并发约 25–30s），
  自然度是小模型第一梯队；但 **v1.0 中文发音有错**（§3）、英文 OOV 要预处理，
  且自然度仍不等于 Edge（云端的模型体量和数据量不是一个量级）；
- **MeloTTS**：中文稳（0% CER）、RTF 4.4×，但单音色，做不了多说话人；
- **质量真正接近/超过 Edge 的本地模型**（CosyVoice2-0.5B、F5-TTS、IndexTTS、GPT-SoVITS 等）都是
  0.3B+ 参数，**CPU 上实时率远低于 1**（5s 音频要几十秒），必须 GPU；有 GPU 后才谈得上"双好"。

**实用建议（不二选一）**：
1. **质量优先**：保留 Edge 做发布成品，本地 TTS 只做**断网兜底/离线模式**（Piper 或 Melo 单音色足够）；
2. **离线优先且能接受轻微发音风险**：用 Kokoro（建议换 v1.1-zh 并逐音色抽检），时间上仍比 Edge 网络快；
3. 有 GPU 后：再评估 CosyVoice2/F5 这类"大一点但质量接近 Edge"的本地模型，那时才可能真正"双好"。

> 提醒：以上"质量"判断基于可懂度（ASR 回读）+ 公开的模型定位，**自然度是主观项**；
> 请先听 `work/local-tts-eval/` 里的同句样例（尤其 Edge vs Kokoro vs Piper），再定取舍。
