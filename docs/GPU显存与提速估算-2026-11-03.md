# 上 GPU 的显存 / 提速估算（2026-11-03）

> 问题："上 GPU 的话这些模型大概占多大显存？"
> 说明：**本机无 CUDA，以下均为按模型体积/参数量的估算区间**（含运行时开销），不是实测；
> 数值口径：显存 ≈ 权重 × 1.2–1.5（运行时/arena）+ 0.3–0.6GB CUDA context + 激活（与音频长度有关）。

---

## 1. 各阶段/模型显存估算

### 1.1 现有流水线（CPU 上已用到的）

| 阶段 / 模型 | 权重体积 | GPU 显存估算 | 备注 |
|---|---|---|---|
| probe / merge / build / burn / mark | — | ≈0（ffmpeg） | 烧录可用 NVENC，占 ~0.3–0.5GB 临时 |
| ASR：whisper small（fp16） | 0.46GB | **0.7–1.0GB** | faster-whisper/CTranslate2 |
| ASR：whisper medium（fp16，当前中文默认） | 1.46GB | **1.8–2.2GB** | 同上 |
| ASR：whisper large-v3（fp16，可选升级） | ≈3.1GB | **3.5–4.5GB**（int8 量化约 2GB） | 质量更高，GPU 才跑得动 |
| diarize：pyannote 分割 5.7MB + 声纹 38–100MB + VAD 0.6MB | <0.15GB | **0.4–0.8GB** | ONNX Runtime CUDA，模型很小，主要是 context/arena |
| 翻译 / 成本 | — | 0（网络/CPU） | — |

> 现有链路里 **最吃显存的是 ASR**（medium ≈2GB、large-v3 ≈4GB），diarize 不到 1GB。

### 1.2 本地 TTS 候选

| TTS 模型 | 参数量/权重 | GPU 显存估算 | 说明 |
|---|---|---|---|
| Piper（VITS，每音色 63MB） | ~16M | **0.2–0.4GB** | 极小；4 并发也才 ~1–1.5GB |
| MeloTTS zh+en（170MB） | ~42M | **0.3–0.5GB** | 单女声 |
| Kokoro-82M（326MB fp32） | 82M | **0.5–0.8GB** | 54 音色；fp16/int8 还能更小 |
| CosyVoice2-0.5B | 0.5B | **2.5–4GB** | LLM + flow matching + vocoder；质量接近 Edge，PyTorch |
| F5-TTS（~330M） | 0.33B | **2–3GB** | 零样本克隆，需参考音频 |
| GPT-SoVITS（含 BERT/HuBERT） | ~0.4GB 权重 | **2–3GB** | 克隆，CPU 慢 |
| IndexTTS2（~1.5B 级） | ~3GB | **5–8GB** | 高质量/克隆，较重 |

### 1.3 其它（开 BGM 时）

| 模型 | 权重 | GPU 显存估算 |
|---|---|---|
| demucs htdemucs | 80MB | **1.5–2.5GB**（分块推理，与音频长度相关） |

## 2. 整条链路的峰值显存（关键）

阶段是**顺序执行**的，峰值取决于"最重的那一段"和是否会**并发**：

| 组合 | 峰值估算 |
|---|---|
| ASR medium + diarize 并行（OPT-5 现状）+ Kokoro TTS | **≈2.5–3GB** |
| ASR large-v3 + diarize 并行 + Kokoro | **≈4.5–5GB** |
| 上面 + demucs（BGM 分离，不重叠则不加） | +1.5–2.5GB |
| 换 CosyVoice2 做 TTS（单实例） | **≈4–5GB**（大 TTS 与 ASR 顺序执行，不叠加） |
| CosyVoice2 **4 并发** | 每个进程 ~3GB → **12GB+**（不划算，建议单实例串行或 2 并发） |
| IndexTTS2/GPT-SoVITS + large-v3 + demucs | **8–12GB** |

**结论（按显卡档位）**：

| 显存 | 能干什么 |
|---|---|
| 4GB（GTX 1650 级） | 只够 whisper small + Piper/Kokoro，ASR medium 勉强；不推荐 |
| **6–8GB（3060 laptop / 4060 级）** | **当前全链路 + Kokoro/Piper/Melo 本地 TTS 够用**（ASR medium + diarize + TTS 峰值 ~3GB，留余量） |
| **12GB（3060 12G / 4070 级）** | 舒适：large-v3 ASR + CosyVoice2/F5 + demucs，仍有余量 |
| 16–24GB | 1.5B 级 TTS（IndexTTS2）、高并发/批量、或以后微调 |

## 3. 提速预期（与显存一起看）

| 阶段 | CPU 实测 | GPU 估算 | 依据 |
|---|---|---|---|
| ASR medium（10min） | 217s | **25–40s** | CTranslate2 CUDA，whisper 类 6–9× |
| diarize（10min，含 VAD/二次聚类） | 100.8s | **20–25s** | 小卷积模型，4–6× |
| Piper TTS | RTF 10–12× | RTF 30–60×+ | 模型极小，GPU 收益大 |
| Kokoro TTS | RTF 2.6–3.2× | RTF 10–20× | 82M 卷积/注意力 |
| CosyVoice2（质量接近 Edge） | CPU 实时率 <1 | **接近/超过实时** | 0.5B + PyTorch，GPU 才可用 |
| demucs | 47.9s/60s 音频 | ~5–10s | torch CUDA，10× 级 |
| **整条 10min 链路** | 396s（好窗口） | **≈205–240s** | 瓶颈变成网络 TTS/翻译（见 OPT-9 评估） |

> 注意：如果本地 TTS 也上 GPU，dub 阶段不再是网络瓶颈，10min 链路有望再降到 **~100–150s**（ASR 30 + 翻译 5 + 本地 TTS 30–60 + 其他）。

## 4. 部署成本（不只是买卡）

1. **sherpa-onnx 需要 GPU 版**：当前 PyPI 的 `sherpa-onnx` 是 CPU 轮子；GPU 要么用其 CUDA 构建，要么换成 `onnxruntime-gpu` 路径；
2. **faster-whisper**：要装 cuDNN/CUDA 对应版本（CTranslate2 CUDA），版本不匹配会直接报错；
3. **demucs / CosyVoice / F5 / GPT-SoVITS**：需要 `torch+cu`（约 2–3GB 安装包）；
4. 显存是"每个进程"占的：我们的架构是**子进程调用**（ASR/TTS/分离各自进程），CUDA context 会每个进程各占 0.3–0.6GB，估峰值时要按"同时活着的进程数"算；
5. 建议保留 **CPU 可回退**：GPU 不可用时自动降级（现有 `--*-python` 指定解释器的机制可以复用）。

---

## 5. 一句话回答

- **要跑现有全链路 + 小本地 TTS（Piper/Kokoro/Melo）：6–8GB 显存就够**（峰值约 2.5–3GB，留余量）；
- **要用"质量接近 Edge"的本地 TTS（CosyVoice2/F5）+ large-v3 ASR：12GB 起步**（峰值 4–5GB，舒适 12GB）；
- 想上 1.5B 级 TTS 或高并发批量：16GB+；
- 显存之外还要留 **部署工作量**（GPU 版 sherpa/ORT、cuDNN、torch-cu），不是插卡即用。
